# IDSM — SaigonBank Device Hub

Internal IT device / asset management app for SaigonBank. Two top-level apps:

| Folder | What it is | Status |
|--------|-----------|--------|
| [`frontend/`](frontend/) | React + Vite + TypeScript + Tailwind web app (pragmatic DDD), npm workspace | Implemented against in-memory mocks |
| [`backend/`](backend/) | NestJS 11 + Prisma 7 + PostgreSQL API, standalone pnpm project | Module `identity` (auth) implemented |

## Run

### Frontend

```bash
npm install        # from the repo root — installs the frontend workspace
npm run dev        # http://localhost:5173
npm test           # vitest
npm run build      # type-check + production build
```

Each script is a thin alias for the matching `-w frontend` command.

### Backend

`backend/` is **not** an npm workspace — it has its own `pnpm-lock.yaml`. Run everything from
inside `backend/`; see [`backend/README.md`](backend/README.md).

```bash
cd backend
pnpm install
npx prisma migrate dev     # applies backend/prisma/migrations
pnpm start:dev             # http://localhost:3000
```

## Database

Schema lives in [`backend/prisma/schema.prisma`](backend/prisma/schema.prisma); migrations are
generated by Prisma Migrate into [`backend/prisma/migrations/`](backend/prisma/migrations/).

- Change the schema → `npx prisma migrate dev --name <verb_noun>` → commit the schema and the new
  migration folder together.
- Never edit a migration that has been merged; fix forward with a new one.
- The ERD in the internship report (BCTT-HKTT, section 3.2.1) must be updated whenever the schema
  shape changes.
